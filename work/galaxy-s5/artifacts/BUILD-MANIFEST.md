## Boot-only DTBH correction after first boot loop

The phone's actual Samsung bootloader diagnostics identify chip `0x152e`, platform `0x1e92`, subtype `0x7d64f612`, hardware revision `0x0a`. The original native boot image's single DTBH entry had correct chip and revision range, but dtbTool-exynos default platform `0x50a6` and subtype `0x217584da`, so the bootloader could not match that DTB. The embedded revision-10 FDT's root model, compatible strings, and `model_info-*` properties match the stock revision-10 FDT; only DTBH selection metadata was wrong. The actual bootloader loads the kernel at `0x40008000`, ramdisk at `0x42000000`, and DT at `0x41f00000`, so nominal boot header addresses are not literal load locations on this phone.

The independently reviewed DTBH-only image was `boot-k3gxx-dtbh-cd25de6c.img` (13,490,176 bytes; SHA256 `cd25de6c65609309f9e93fb4ec2564304ee752eac76704d9080b3d8cc8ae4d05`). Relative to the first installed boot image, only the two DTBH platform/subtype fields and the Android boot header SHA1 image ID changed (26 differing bytes total). Kernel, ramdisk, FDT payload, command line, addresses, size, and rootfs were unchanged. The corrected standalone DT image is `dt-k3gxx-dtbh-f6aac8da.img` (SHA256 `f6aac8da35c945bc982d10fccf29535a4692ea50669f5d323493c9c8b1228f6b`) for later replacement of the installed `/boot/dt.img`. The source script `source/patch-boot-dtbh.py` reproduces the exact DTBH-only image, including the Android image ID.

## ARM r11 suspend fix after native crash log

The corrected DTBH let the physical phone boot Linux, but a warm-captured `last_kmsg` showed all CPUs crash around 2.318 seconds. The first fault was `__cpu_suspend_save+0x64` at `ldr r1,[r11,#-28]`, with frame pointer `r11=0` and fault address `0xffffffe4`. This kernel has `CONFIG_FRAME_POINTER=y`. Its ARM `cpu_v7_do_suspend` assembly saved `r4-r10,lr`, overwrote callee-saved `r11` with a CP15 register read, then restored only `r4-r10`; it therefore corrupted the C caller's frame pointer. The minimal source patch `preserve-r11-in-cpu-v7-suspend.patch` saves and restores `r11` as well. That routine makes no nested calls while the stack has the extra register, so no 8-byte call-boundary alignment change is introduced. The kernel APKBUILD now builds `linux-samsung-k3gxx=3.10.9-r1` with this patch and the explicit DTBH IDs.
